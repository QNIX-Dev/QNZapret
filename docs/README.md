# Документация QNZapret

Документация описывает код в репозитории. Наличие реализации не означает, что
она собирается на текущем хосте или проверена в конкретной сети.

| Документ | Что в нём |
| --- | --- |
| [Архитектура](architecture.md) | Назначение, состав репозитория, Flutter-слои, пути трафика и границы платформ |
| [Android](android.md) | VPN, TUN-to-SOCKS, стратегии, Telegram, lifecycle и диагностика |
| [Linux](linux.md) | D-Bus, права, NFQUEUE, Telegram, обновления компонентов, пакеты и восстановление |
| [Контракт runtime](runtime_bridge_contract.md) | Dart API, каналы, конфигурация, snapshot, события и платформенные различия |
| [Разработка и проверки](development.md) | Подготовка среды, команды, тесты, smoke, CI и известные проблемы исходников |

Начните с архитектуры, затем читайте документ нужной платформы. При изменении
API сверяйте контракт; команды сборки и границы проверок собраны в руководстве
разработчика. Корневые [README](../README.md) и [AGENTS.md](../AGENTS.md)
содержат краткий вход и правила работы.

Здесь нет отдельных handoff, планов «следующего этапа» и датированных отчётов.
История изменений остаётся в Git. При изменении поведения обновляйте
соответствующий раздел, а не создавайте ещё одно описание той же подсистемы.
