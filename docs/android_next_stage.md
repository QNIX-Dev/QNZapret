# Следующий этап: актуальный Android non-root

Приоритет пользователя, зафиксирован 12 октября 2026 года **после завершения
текущего Linux/документационного среза**. Этот файл — план и критерии приёмки,
а не отчёт о выполнении. Изменения Android runtime в рамках очистки docs не делались.

## Цель

Обновить и доработать Android-маршрут для устройств без root, довести основные
сценарии до функционального состояния, собрать приложение и подготовить всё
для самостоятельного тестирования пользователем на смартфоне.

## Объём

1. Сначала воспроизвести известный дефект: простое открытие шторки с плиткой
   QNZapret (без нажатия) завершает другие VPN. Проверить QS callbacks и
   чтение snapshot: отрисовка/обновление плитки не должны запускать наш
   VpnService, вызывать prepare/establish или останавливать чужой VPN.
   Проверить актуальные исходники/контракт, toolchain и Android зависимости;
   воспроизвести ошибки по logs/tests. Сохранить архитектуру и данные пользователя.
2. Сверить используемые компоненты, route-provider и протокольные решения с
   актуальными официальными upstream. Оценить лицензии и совместимость;
   обновление Linux Python core не переносится в Kotlin автоматически.
3. Доработать VPN consent, foreground lifecycle, TUN/JNI/SOCKS5/protect/bind,
   DNS/Private DNS, IPv4/IPv6, start/stop/revoke, background/QS/notification.
4. Проверить HTTP/TLS/QUIC и реальные целевые ресурсы: connect, payload,
   throughput, CPU/память, timeouts/retries и отсутствие потери обычного direct
   трафика. Не подменять сетевые проверки успешной сборкой.
5. Обновить Telegram Kotlin path: setup до входа/после входа, public/local
   routes, TLS verification, DC/media ordering, cache/pool/cooldown, text,
   photo/video, voice/circle/file upload и отсутствие зависающих bridges.
6. Выравнять Telegram listener/handshake/bridge flags и UI: зелёный статус не
   должен появляться только из-за открытого порта. Подготовить понятные ошибки
   и диагностику; native log stream оценить как часть этого UX.
7. Определить Android-compatible доставку обновляемых route data/компонентов.
   Не запускать Linux root updater, не загружать исполняемый код без отдельного
   Android design и не выдавать placeholder signed-config за готовую функцию.
8. Проверить native dependencies/toolchain, JVM/Dart/widget tests, release APK
   и AAB. Согласовать Android/UI/Flutter version metadata и безопасный upgrade
   путь. Production signing нельзя считать настроенным пока используется debug key.

Полностью прозрачный direct MTProto transport и обязательный удалённый relay
не подразумеваются автоматически: они требуют отдельного решения. Основной
пользовательский маршрут должен работать без root и собственного VPN/SOCKS
сервера, с честно обозначенными ограничениями сети.

## Передача пользователю

Подготовить:

- installable release APK с именем версии/commit, SHA256 и понятным способом
  установки/обновления; AAB — дополнительный build artifact;
- перечень реально выполненных проверок и известных ограничений;
- короткую инструкцию VPN permission/notification/Telegram confirm;
- сценарий проверки обычного интернета, YouTube, Telegram text/media/uploads,
  stop/restart/background, mobile/Wi-Fi и доступного IPv6;
- безопасный сбор диагностики и критерии ожидаемого результата по каждому шагу;
- способ отката без удаления пользовательских данных.

При доступном ADB выбрать нужное устройство явно. Установка — с сохранением
данных (`adb install -r` там, где совместима подпись); не сбрасывать аккаунты,
не отправлять сообщения от пользователя и не менять личные настройки ради
smoke без отдельного согласования. Если телефон недоступен, подготовить APK
и checklist, честно оставить device-проверки невыполненными.

## Готовность этапа

Сборка и tests проходят, основные ошибки воспроизведены и устранены, status
соответствует фактическому состоянию, APK пригоден для установки. Работа на
смартфоне/сети подтверждается отдельно пользователем или согласованным ADB smoke.
Не объявлять «работает везде» на основании одного устройства/провайдера.
